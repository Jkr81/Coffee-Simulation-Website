01 — Project

Brief Description

The Coffee Station is an interactive XR experience designed to teach users the correct sequence of making coffee using a virtual espresso machine. Built in Unity, it guides users through grabbing ingredients, placing them into the machine, brewing, and finally serving a cup to a waiting guest — all within a richly detailed café environment.

The simulation prioritizes guided interaction over open exploration — every action produces visible, satisfying feedback, and fail-safe systems prevent softlocks or broken states, making it accessible to first-time XR users.

🎯

Objective

Teach users a structured coffee-making sequence while introducing core XR mechanics: grabbing, placing, and pressing in a physically-grounded environment.

🏗️

Platform

Unity 3D with XR Interaction Toolkit. Tested with the XR Device Simulator for desktop development and compatible with VR headsets.

👤

Audience

Beginners to XR. The experience is designed to be immediately understandable without prior VR experience, using clear in-world text prompts.

⏱️

Session Length

A single run takes approximately 2 minutes. A Replay Training button allows immediate repetition for skill reinforcement.

02 — Core Loop

How It Plays

The simulation follows a tight, satisfying loop with a clear start and end. Every step is gated — the player cannot proceed without completing the previous one.

· · ·
01

Welcome Panel

Player faces the intro panel in the café. Controller diagram and keybindings are displayed. A large "Press Begin" button unlocks the session.

02

Gather Ingredients

Player grabs the water container and coffee beans from the counter using the Grip button. Objects are highlighted and grabbable via XR Interaction Toolkit.

03

Load the Machine

Ingredients are placed into the machine's designated zones. The machine tracks hasWater, hasBeans, and hasCup states internally.

04

Brew

With all conditions met, the player presses the red brew button. The button glows yellow during brewing, then turns green — "Coffee done!" appears in the console overlay.

05

Serve the Guest

Player picks up the finished cup and walks it to the waiting café guest. A trigger zone detects delivery.

06

Shift Complete

"Shift Complete" panel appears summarizing what was learned. Player can hit Replay Training to restart the full loop.

03 — Highlight

Interesting Interactions

Several design choices make this simulation stand out from a generic XR tutorial. Each feature below represents a deliberate decision to improve user experience and prevent frustration.

State Machine

Gated Brewing Logic

The machine maintains a live state for water, beans, and cup. Brewing is impossible unless all three are present — and once brewed, a boolean lock prevents any repeat action. This prevents exploitation and reinforces the correct sequence.

Fail-Safe

Object Respawn System

Every interactable object stores its original world transform at startup. If it falls off the counter or out of bounds, it silently teleports back — no softlocks, no frustration, no restart needed.

Visual Feedback

Dynamic Button Color

The brew button cycles through three meaningful states: red (idle/locked), yellow with glow (brewing in progress), and bright green (coffee ready). The color shift is immediately readable even in VR peripheral vision.

World-Space UI

Diegetic Instruction Panels

Instructions live inside the world as floating panels — not as HUD overlays. This preserves immersion while keeping guidance clear. The intro and completion panels are interactable XR objects themselves.

Audio

Brewing Sound Feedback

An espresso machine sound plays during the brew coroutine, bridging the gap between button press and result. The temporal audio cue signals that the machine is working and builds anticipation.

Guest NPC

Delivery Trigger Zone

The GuestTrigger.cs script wraps the guest character in an invisible trigger zone. Only when coffee is ready AND the cup enters the zone does the completion sequence fire — preventing accidental triggers.

06 — Technical

Implementation

Built in Unity, the simulation relies on two primary C# scripts and a set of Unity components for physics, audio, and UI. All XR interactions leverage the toolkit's built-in Interactable and Interactor system.

Unity (XR Setup) C# Scripting XR Interaction Toolkit TextMeshPro XR Simple Interactable Ray Interactor Coroutines World-Space Canvas AudioSource ParticleSystem Rigidbody / Colliders XR Device Simulator

Core Brewing Logic — CoffeeMachineSimple.cs

The machine checks all required states before allowing the brew coroutine to start. Once fired, a boolean lock prevents any further brewing until the scene is reset.

// Only brew if ingredients are present and not already brewing
if (hasWater && hasBeans && hasCup && !isBrewing)
{
    StartCoroutine(BrewCoffee());
}

private IEnumerator BrewCoffee()
{
    isBrewing = true;
    brewButton.color = Color.yellow;       // visual feedback
    audioSource.Play();                   // brewing sound
    yield return new WaitForSeconds(3f);
    coffeeReady = true;
    brewButton.color = Color.green;        // done!
    Debug.Log("Coffee done!");
}

Delivery Detection — GuestTrigger.cs

A trigger collider on the guest NPC fires only when the cup enters its zone AND the machine has set coffeeReady to true. A triggered boolean prevents the completion panel from firing more than once.

07 — Challenges

Problems & Solutions

Five core issues emerged during development, each resolved through iteration and targeted design changes.

  • 🔄
    Objects falling out of bounds

    Implemented a respawn system that stores each object's original world transform at Awake() and resets position when it falls below a threshold Y value. No restarts needed.

  • 🎮
    XR buttons not responding

    Switched from custom collider-based buttons to XR Simple Interactable components. Ensured the Ray Interactor was active and that all button objects had properly configured colliders.

  • 💧
    Water not staying in cup

    Removed conflicting Rigidbody components from the water object and made it a child of the cup transform, so it moves naturally with the cup during pickup and placement.

  • 📋
    Completion panel not appearing

    Panel was left enabled in the scene. Switched to setting it inactive in Awake() and activating it programmatically only after the delivery trigger fires correctly.

  • 🔒
    Multiple brewing attempts

    Added an isBrewing boolean that is set to true at the start of the coroutine. Subsequent button presses check this flag first and exit early if brewing has already occurred.
